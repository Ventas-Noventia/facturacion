FACTURACION NOVENTIA v1.16.4 - ACTUALIZACION ACUMULADA DESDE v1.15.2

CORRECCION DEL ERROR DE ARRANQUE
El servidor de v1.16.4 depende de archivos introducidos en versiones previas,
incluido backend/services/portalFacturasService.mjs. El parche anterior incluia
solo los cambios desde v1.16.3. Este paquete incluye TODOS los archivos cambiados
desde la base v1.15.2, sin necesitar instalar los parches intermedios.

Conserva la configuracion de la API que ya funciona. No requiere npm install.

INSTALACION RECOMENDADA DEL PAQUETE ACUMULADO
1. Deten el servidor con Ctrl+C.
2. Descomprime actualizacion-acumulada-noventia-v1.16.4.zip en Descargas.
3. Desde Terminal ejecuta el instalador indicando la carpeta EXISTENTE:
   node ~/Downloads/actualizacion-acumulada-noventia-v1.16.4/instalar.mjs "/Users/papu/Documents/Noventia/DashboardFacturacion/facturacion-dinamica-v1.11.1"
4. El instalador verifica los archivos y respalda los archivos de codigo que va a
   reemplazar. Copia archivos individuales y agrega los que faltan. Conserva
   .env, credenciales, backend/data, backend/storage y node_modules.
5. Dentro de la carpeta de tu proyecto ejecuta npm start.
6. Debe mostrar facturacion-dinamica-v1@1.16.4 y Facturacion: http://localhost:3000.

Si tu navegador coloca la descarga en otra carpeta, ajusta solo la ruta del
instalador. La carpeta de proyecto es la que ya usas; no hay que renombrarla.
El instalador no inicia servidores, ejecuta SQL, instala paquetes ni despliega.

SUPABASE DESPUES DE COMPROBAR EL ARRANQUE
1. En Supabase > SQL Editor ejecuta supabase/revisar_duplicados_pedidos.sql.
   Es solo lectura. Las DOS consultas deben devolver cero filas.
2. Si aparecen filas, revisa esas facturas; no elimines registros para continuar.
3. Si ambas estan vacias, ejecuta supabase/012_facturas_pedido_activo.sql en otra
   consulta. No repitas schema.sql ni las migraciones antiguas 005 u 008.
La migracion es una transaccion que crea indices para una factura activa por
folio y por ID API. Sustituye el indice antiguo que bloqueaba tambien canceladas.
No modifica ni elimina facturas. Ningun SQL remoto fue ejecutado por este paquete.

VALIDACION
Sigue VALIDACION_COMPRAS.md. Las pruebas npm test usan datos simulados y no
necesitan credenciales reales. El timbrado sigue siendo MOCK, sin valor fiscal.
El bloqueo de operaciones protege un proceso de la aplicacion; los indices de
Supabase protegen la creacion de duplicados entre instancias. El futuro PAC
necesita ademas idempotencia y conciliacion antes de operar en produccion.
